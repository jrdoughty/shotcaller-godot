# M6 - Editor mode panel: top-right modes (1-4), per-mode left panel, right-click move

## Goal

The runtime editor's left panel (map/editor/editor_ui.gd `ToolPanel`, 300px wide)
crams file operations, three tool sections, the Move section, Undo/Redo and the
log into ONE `ScrollContainer`, so controls scroll out of reach. Re-home the
**mode choice** into a new 4-button panel at the **top-right** of the screen
(keyed 1-4), show **only the active mode's tools** in the left panel pinned (no
scrolling — only the log scrolls), and replace the separate "Move things" mode
with **right-click select-and-move** inside the Lanes and Buildings modes.

Owner decisions (confirmed 2026-11-26, do not re-litigate):

1. Right-click move is **kind-scoped**: Lanes mode drags lane points only;
   Buildings mode drags buildings only.
2. Re-pressing the active mode (button or number key) **deselects** to no tool;
   Escape also exits, as today.
3. The editor **boots into Map mode (3)**.
4. The mode panel is a **horizontal row at the top-right corner**.

## Fixed decisions (do not re-litigate)

1. **ONE signal replaces four.** `editor_ui.gd` gets a single
   `signal mode_requested(mode_name: String)` and a host-facing
   `set_mode_active(mode_name: String, active: bool)` (same signature as M5).
   `lane_mode_requested` / `building_mode_requested` / `tile_mode_requested` /
   `move_mode_requested` are removed. `map_editor.gd` wires
   `ui.mode_requested.connect(_set_mode)`.
2. **Mode vocabulary changes in `map_editor.gd`.** `mode` takes
   `""`, `"lane"`, `"building"`, `"map"`, `"tile"`. The `"move"` mode is
   deleted. `"map"` is a UI-only mode: `_unhandled_input` routes NO canvas
   clicks to it (file buttons already work through the panel).
3. **Keep every picker ALIVE; only toggle visibility.** Hidden Controls keep
   their state. Building placement reads the lane name (subtype) from the lane
   dropdown even while Lanes mode is hidden — that getter must keep working;
   do not free or rebuild controls per mode.
4. **All editor-free logic is untouched** (lane_logic, building_logic,
   tile_brush_logic, map_scaffold, map_validator, map_store) and the dock
   (addons/map_editor/) is untouched — M5 decision 4 stands.
5. **UndoRedo discipline stands** (the bug that motivated it is pinned in
   M5/tests): never open an action that might be abandoned; the runtime
   `UndoRedo` has no `cancel_action()`. `_grab_move_target` still only records
   into `_drag`; the action is created at commit. All `map_editor.gd` changes
   here re-home EXISTING commit paths; do not restructure `_commit_pending`
   call sites.
6. **Camera policy stands**: mouse wheel zooms, middle-drag pans; wheel over
   either panel must NOT zoom (the panels `mouse_filter = STOP`, existing
   policy). giving the log its own scrollbar (see below) keeps that.
7. **Digits are plain-shortcut only.** Only `KEY_1..KEY_4` (main row, no numpad),
   only with no Ctrl/Alt/Meta, and only when no `LineEdit` has focus (the map
   name field must accept typed digits). Focused Controls normally consume
   keys before `_unhandled_input`, but the guard makes it deterministic.
8. **No `.ci-repro/` edits.** It is a frozen snapshot checkout that merely
   contains older copies of these files. Only edit `map/editor/` and the listed
   test/doc files.

## UI contract

```
screen
├── UILayer/EditorUI (Control, full rect, MOUSE_FILTER_IGNORE)
│   ├── ModePanel (PanelContainer, MOUSE_FILTER_STOP, top-right corner, 8px margin)
│   │   └── ModeButtons (HBoxContainer)
│   │       ├── "Lanes (1)"      toggle, ButtonGroup
│   │       ├── "Buildings (2)"  toggle, ButtonGroup
│   │       ├── "Map (3)"        toggle, ButtonGroup
│   │       └── "Tiles (4)"      toggle, ButtonGroup
│   └── ToolPanel (PanelContainer, MOUSE_FILTER_STOP, left-wide, 300px)  [restructured]
│       └── Tools (VBoxContainer)                    ← NO ScrollContainer anymore
│           ├── MapTools       (VBox)  visible iff mode == "map"
│           ├── LaneTools      (VBox)  visible iff mode == "lane"
│           ├── BuildingTools  (VBox)  visible iff mode == "building"
│           ├── TileTools      (VBox)  visible iff mode == "tile"
│           ├── HistoryRow     (HBox)  ALWAYS visible: [Undo] [Redo]
│           └── Log (RichTextLabel)    ALWAYS visible, EXPAND_FILL,
│                                     fit_content = false, scroll_following = true
│                                     ← the ONLY scrolling region (its own scrollbar;
│                                       mouse_filter STOP so the scrollbar can be dragged;
│                                       it sits inside ToolPanel whose STOP already keeps
│                                       log clicks from reaching map tools)
```

Per-mode container contents (all moved from the current `_build()`, tooltips
kept verbatim, order kept):

- `MapTools`: `_map_option` (+ its `item_selected` → name prefill), row
  `Open` / `Refresh` / `New map`, `_name_entry`, row `Save` / `Delete` /
  `Validate` / `Play`, `Exit`.
- `LaneTools`: `_lane_option`, row `New lane`. (The `Draw lanes` toggle dies —
  the Lanes (1) button is the mode.)
- `BuildingTools`: `_building_option`, `_team_option`. (The `Place buildings`
  toggle dies; the `Move things` toggle dies.)
- `TileTools`: `_mirror_toggle` (default pressed), `_brush_option`,
  `_block_option`, `_tile_option`.

The `_section()` helper becomes unused → delete it (no headers left; the
top-right button names the section).

Mode tooltips (concise, per button):

- Lanes: "Left-click adds a snapped point to the selected lane. Right-click drag moves an existing lane point. Escape exits."
- Buildings: "Left-click places the selected building under the selected team. Right-click drag moves a placed building. Escape exits."
- Map: "File operations for the map being edited: open, save, validate, play, exit."
- Tiles: "Left-click paints the selected tile, right-click erases, drag works. Escape exits."

## Implementation sketch

### Step 1 — `map/editor/editor_ui.gd`

1. Constants:

   ```gdscript
   const PANEL_WIDTH := 300.0          # unchanged
   const MODE_LABELS := {"lane": "Lanes (1)", "building": "Buildings (2)",
                         "map": "Map (3)", "tile": "Tiles (4)"}
   const MODE_KEYS := {KEY_1: "lane", KEY_2: "building",
                       KEY_3: "map", KEY_4: "tile"}
   const MODE_TOOLTIPS := { ... the four tooltips above ... }
   ```
   GDScript dictionaries preserve insertion order; iterate `MODE_LABELS` for
   both the buttons and the containers so key order is Lanes, Buildings, Map,
   Tiles.

2. Members: replace `_lane_toggle/_building_toggle/_tile_toggle/_move_toggle`
   with `var _mode_buttons: Dictionary = {}` (mode name → Button) and
   `var _mode_tools: Dictionary = {}` (mode name → Control). All other members
   (`_map_option`, `_lane_option`, `_building_option`, `_team_option`,
   `_brush_option`, `_tile_option`, `_block_option`, `_mirror_toggle`, `_log`,
   `_block_values`, `_picker_tiles`) keep their names — the headless tests and
   the host read them.

3. `_build()`: build `ModePanel` + `ModeButtons` first (snippet):

   ```gdscript
   var mode_panel := PanelContainer.new()
   mode_panel.name = "ModePanel"
   mode_panel.mouse_filter = Control.MOUSE_FILTER_STOP
   add_child(mode_panel)
   mode_panel.set_anchors_and_offsets_preset(Control.PRESET_TOP_RIGHT,
           Control.PRESET_MODE_MINSIZE, 8.0)
   mode_panel.grow_horizontal = Control.GROW_DIRECTION_BEGIN
   var row := HBoxContainer.new()
   row.name = "ModeButtons"
   mode_panel.add_child(row)

   var group := ButtonGroup.new()
   group.allow_unpress = true
   for mode_name in MODE_LABELS:
       var button := Button.new()
       button.text = MODE_LABELS[mode_name]
       button.toggle_mode = true
       button.button_group = group
       button.tooltip_text = MODE_TOOLTIPS[mode_name]
       button.toggled.connect(_on_mode_toggled.bind(mode_name))
       row.add_child(button)
       _mode_buttons[mode_name] = button
   ```

   then restructure `ToolPanel` per the UI contract: drop the
   `ScrollContainer` + inner `Tools` scroll box entirely; `ToolPanel`'s child
   is one `VBoxContainer` named `Tools` that holds the four per-mode
   `VBoxContainer`s (built by iterating `MODE_LABELS`, filling each with its
   controls), `HistoryRow` (the existing Undo/Redo buttons), and the log

   ```gdscript
   _log.fit_content = false
   _log.scroll_following = true
   _log.mouse_filter = Control.MOUSE_FILTER_STOP   # its scrollbar must be draggable
   _log.size_flags_vertical = Control.SIZE_EXPAND_FILL
   ```

   Keep `log_line()`'s 80-line trim. Keep the signal name prefill hookup on
   `_map_option`. Keep `refresh_map_list()` / `refresh_tile_picker()` calls at
   the end of `_build()`.

4. Signals & handlers: declare `signal mode_requested(mode_name: String)`;
   delete the four old mode signals and `_emit_request`'s mode cases (the
   `_emit_request`/`_emit_no_payload` string-dispatch keeps only non-mode
   entries: undo/redo/file ops). Add:

   ```gdscript
   func _on_mode_toggled(active: bool, mode_name: String) -> void:
       mode_requested.emit(mode_name if active else "")
   ```

5. `set_mode_active()` rewrite (kept name, same call sites in the host):

   ```gdscript
   func set_mode_active(mode_name: String, active: bool) -> void:
       var shown := active and mode_name != ""
       for m in _mode_tools:
           _mode_tools[m].visible = shown and m == mode_name
       for m in _mode_buttons:
           _mode_buttons[m].set_pressed_no_signal(shown and m == mode_name)
   ```
   Delete `_toggle_for()`. The ButtonGroup prevents double-lit buttons and
   `set_pressed_no_signal` prevents echo loops back into `mode_requested`.

6. Getters (`selected_lane_name`, `selected_building_scene`, `selected_team`,

### Step 2 — `map/editor/map_editor.gd`

1. Header comment: replace the "plus a Move tool for repositioning …" sentence
   with the right-click move description and the mode keys.

2. `_ready()`: after `_connect_ui()` add `_set_mode("map")` (boot state).

3. `_connect_ui()`: delete the four mode-signal connections and add
   `ui.mode_requested.connect(_set_mode)`. `_set_mode` already handles `""`
   (commit + deselect previous) — no change needed there beyond removing the

4. `_unhandled_input()`: inside the existing
   `event is InputEventKey and event.pressed and not event.echo` block, keep
   Escape, Ctrl+Z, Ctrl+Y as-is and add:

   ```gdscript
   var focused := get_viewport().gui_get_focus_owner()
   if not (focused is LineEdit) and not event.ctrl_pressed \
           and not event.alt_pressed and not event.meta_pressed \
           and EditorUI.MODE_KEYS.has(event.keycode):
       var target: String = EditorUI.MODE_KEYS[event.keycode]
       _set_mode("" if target == mode else target)
       get_viewport().set_input_as_handled()
       return
   ```
   `EditorUI` is the preloaded const in this file, so its constants are in
   scope.

5. Mode routing at the bottom of `_unhandled_input()` becomes:

   ```gdscript
   if mode == "lane":
       _handle_lane_input(event)
       _handle_drag_input(event, "lane")
   elif mode == "building":
       _handle_building_input(event)
       _handle_drag_input(event, "building")
   elif mode == "tile":
       _handle_tile_input(event)
   # "map" mode: no canvas clicks — the panel buttons act through signals.
   ```

6. `_handle_lane_input` and `_handle_building_input` keep their LEFT-button
   behavior (add point / place building) and stay LEFT-only; right-button
   events fall through to `_handle_drag_input`. Delete `_handle_move_input`.

7. Rename/make generic the drag entry point:

   ```gdscript
   func _handle_drag_input(event: InputEvent, kind: String) -> void:
       if event is InputEventMouseButton:
           var click := event as InputEventMouseButton
           if click.button_index != MOUSE_BUTTON_RIGHT:
               return
           if click.pressed:
               _grab_move_target(click.position, kind)
           else:
               _commit_pending()
           get_viewport().set_input_as_handled()
       elif event is InputEventMouseMotion:
           if _drag.is_empty():
               return
           if not (event.button_mask & MOUSE_BUTTON_MASK_RIGHT):
               _commit_pending()  # release eaten by the UI panel (existing rule)
               return
           _drag_move(event.position)
           get_viewport().set_input_as_handled()
   ```
   This is the old `_handle_move_input` with LEFT → RIGHT and a `kind`.

8. `_grab_move_target(viewport_pos: Vector2, kind: String)`: same body, but the
   pick pair becomes kind-scoped:

   ```gdscript
   var best: Dictionary = {}
   if kind == "lane":
       _lanes_pick(viewport_pos, best)
   elif kind == "building":
       _buildings_pick(viewport_pos, best)
   ```
   Everything else — 48px radius refusals, no UndoRedo at grab, lane overlay
   on lane grabs, "Grabbed …" log line — is UNCHANGED. `_lanes_pick`,
   `_buildings_pick`, `_drag_move`, `_commit_drag`, `_node_label` are
   untouched.

9. `_install_map()`: replace the unconditional `_set_mode("")` with

   ```gdscript
   _commit_pending()
   if mode in ["lane", "building", "tile"]:
       _set_mode("")  # an active tool drops on map install; Map mode stays
   ```
   (Boot is Map mode; after New/Open the file controls stay visible.)

## Owner-reported defects (windowed pass, 2026-11-27)

1. **Clicking Buildings (2) left the left panel with no tool box.** Reproduced
   headlessly only after driving a real `Button.set_pressed()` — every existing
   mode test drove `mode_requested.emit()` or the 1-4 keys, which cannot reach
   this bug. Cause: `BaseButton::_unpress_group()` releases the lit button
   BEFORE the clicked one reports `toggled(true)`, so the outgoing mode's
   `toggled(false)` is a group switch; `_on_mode_toggled` read it as "nothing
   selected", emitted `mode_requested("")`, and `_set_mode("")` re-entrantly
   un-pressed the button the engine was mid-press on. Fix: only emit the empty
   mode when `button_group.get_pressed_button()` (a live scan of the group in
   4.7.2-stable `base_button.cpp:723-730`) is null.
2. **Right-click could not grab a building.** Measured headlessly (throwaway
   probe, `three_lane_map` installed): the press reached `_buildings_pick`
   correctly (`route_drag == picker_drag`), but the pick measured distance to the
   node ORIGIN, while a tower's clickable body is 4-68px ABOVE its origin
   (selection circle r=45 at (0,-20)) — press spots 58-68px from the origin were
   refused, silently. Fix: pick against the building's selection footprint
   (`Collisions.setup()` data, the game's own click-select numbers), keep the
   48px viewport budget, record `grab_offset` so a ring grab does not jump the
